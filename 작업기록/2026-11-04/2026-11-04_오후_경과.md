## ④가 한 작업

### 1. 3차 화면 분석과 API 계약 (오전 ~ 12:30)

- 3차 프로젝트 저장소(`SKN35-3rd-4Team`)와 배포 저장소의 최종 Streamlit 화면을 보고, 4차 Django 화면에 옮길 기능을 정리했다.
- 화면에서 일어나는 동작 8개를 기준으로 백엔드와 주고받을 주소를 정해 ①과 공유했다 (12:30).

| 화면 동작 | 요청 |
|---|---|
| 회원가입 · 로그인 · 로그아웃 | `POST /api/users/signup/` · `login/` · `logout/` |
| 새 대화 | `POST /api/langration/sessions/` |
| 질문 · 예제 전송 | `POST /api/langration/chat/` |
| 대화 목록 · 이전 대화 열기 | `GET /api/langration/sessions/` · `sessions/{session_id}/` |

- 정할 때 고민한 것
  - 새 대화 버튼도 백엔드에서 새 대화 번호를 받는 요청으로 둔다 (버튼을 누르면 서버를 부른다는 흐름에 맞춤)
  - 예제 전송과 일반 질문은 같은 채팅 요청을 쓴다
  - 대화 저장은 따로 버튼을 두지 않고 질문을 보낼 때 백엔드가 자동으로 저장한다 (3차와 같음)

### 2. Django 화면 구조 익히기 (직접 해 보기)

이번에는 AI에 맡기기보다 구조를 이해하면서 하려고, 아래 순서로 단계별로 해 보았다.

| 단계 | 한 것 | 배운 것 |
|---|---|---|
| 1 | `/login/` 이 화면에 나오기까지 따라가 보기 | `config/urls.py` → `users/urls.py` → `users/views.py` → `templates/…html` (URL → 뷰 → 템플릿) |
| 2 | 로그인 화면 HTML | `form` · `input` · `button` · `a` 태그, `name` 은 백엔드와 약속하는 이름 |
| 3 | CSS 로 꾸미기 | 색은 `:root` 변수 한 곳에서, `flex` 로 가운데 정렬 · 세로 쌓기, `:focus` · `:hover` |
| 4 | 로그인 버튼 → 백엔드로 보내기 | `fetch` 로 JSON 보내기, CSRF 토큰, 처리 중 버튼 잠금 |
| 5 | 회원가입 화면 | 검사는 화면(빠름)과 백엔드(믿을 수 있음) 두 군데서 |
| 6 | 대화 화면 | HTML(무엇이 있나) · CSS(어떻게 보이나) · JS(누르면 무슨 일) 파일 나누기 |

### 3. 3차 대비 빠진 기능 점검과 보완

1차로 만든 화면을 3차 최종 화면(`streamlit_app.py`)과 하나씩 비교해 보니, 초안 문서와 스크린샷만 보고 만들어 마지막에 추가된 기능이 많이 빠져 있었다. 3차 코드를 기준으로 다시 맞췄다.

| 3차 최종 | 1차 화면 | 보완 |
|---|---|---|
| 첫 인사 "안녕하세요, Langration입니다! 👋"와 쓰는 법 | 없음 | ✅ 첫 화면에 인사 · 쓰는 법 · 추천 질문 |
| "Langration이 생각 중입니다… · ① 바꿀 부분 찾는 중" 진행 표시 | 고정 문구 | ✅ 단계가 끝날 때마다 진행 상자에 한 줄씩 (스트리밍) |
| 답 위 "처리 과정 보기 · 5단계 · 18초" | 없음 | ✅ 접었다 펴는 처리 과정 (가장 최근 답만 펼침) |

## 겪은 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 서버가 `Performing system checks...` 뒤에 아무 말 없이 꺼짐 | 자동 재시작(StatReloader) 쪽에서 조용히 종료 | `runserver --noreload` 로 실행 |
| HTML 을 고쳐도 화면이 안 바뀜 | Django 5.2 는 템플릿을 기억해 둠, `--noreload` 면 다시 읽지 않음 | HTML · Python 을 고치면 서버를 다시 켬 (CSS · JS 는 새로고침만) |
| 실제 서버에서 화면 디자인이 다 깨짐 | Django 가 `static/` 폴더를 못 찾아 CSS 404 | settings 에 `STATICFILES_DIRS = [BASE_DIR / "static"]` |
| 회원가입 아이디 규칙이 작동 안 함 | 최신 브라우저는 `pattern` 의 `-` 를 그대로 쓰면 규칙 전체를 무시 | `\-` 로 고침 → 이후 3차 규칙으로 바꾸며 정리 |
| 결과 패널 코드가 화면 밖으로 밀려남 | 그리드 칸이 긴 코드만큼 늘어남 | `minmax(0, 1fr)` 로 칸 너비 고정 |
| 입력창 안내 글이 코드 글꼴로 보임 | 입력창 줄 클래스(`.row`)가 변경 사항 카드의 `.row` 와 이름이 겹침 | 입력창 쪽을 `.bar` 로 이름 바꿈 |
| VS Code 가 자꾸 버벅임 | `.venv` 파일 1.6만 개 · `data` 문서를 계속 훑음 | 이 PC 의 VS Code 설정에서 두 폴더를 감시 · 검색 대상에서 뺌 |
| ngrok 공유 실패 (`ERR_NGROK_105`) | 저장된 인증 토큰 형식이 맞지 않음 | 계정이 필요 없는 Cloudflare 빠른 터널로 공유 |

## 배운 것

- Django 화면은 **URL → 뷰 → 템플릿** 순서로 연결되고, 화면과 백엔드는 서로의 코드를 몰라도 **주소와 JSON 모양(API 계약)** 만 맞으면 된다.
- 검사는 화면과 백엔드 두 군데서 한다. 화면 검사는 빠르고 친절하지만 우회할 수 있어서, 믿을 수 있는 검사는 백엔드에 둔다.
- 비밀번호는 암호화가 아니라 **해시**(되돌릴 수 없음)로 저장한다. 소금(사람마다 다른 무작위 값)과 반복 계산으로 미리 계산한 표 · 대입 공격을 막는다.
- 스트리밍은 응답 하나를 열어 둔 채 조각을 생기는 대로 보내는 방식이고, 중간 서버(Nginx)가 모아 두지 않도록 버퍼링을 꺼야 한다.
- 만든 것을 기준 자료(3차 최종 코드)와 하나씩 대조해야 빠진 기능이 보인다. 초안 문서만 보고 만들면 마지막에 추가된 기능을 놓친다.
