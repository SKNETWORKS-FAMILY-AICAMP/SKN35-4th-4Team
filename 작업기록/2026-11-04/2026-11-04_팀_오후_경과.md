## 팀이 한 작업

### ① 백엔드

- `users`(아이디 · 비밀번호 해시 · 가입 시각) · `chat_history`(아이디 · 대화 번호 · 질문 · 답) 모델을 만들고 TiDB에 테이블을 만들었다.
- 화면과 약속한 API 8개(가입 · 로그인 · 로그아웃 · 새 대화 · 대화 목록 · 대화 열기 · 채팅)를 구현했다. 채팅은 그래프 단계가 끝날 때마다 한 줄씩 보내는 스트리밍이다.
- ④가 화면을 실제 데이터로 확인하려고 시험 삼아 1차로 연결해 본 코드를 참고해, ①이 전체를 검토해 `dev`에 반영했다.

### ② 배포

- Nginx를 EC2 호스트가 아니라 Docker Compose 안의 컨테이너로 옮겨, `web`(Django + Gunicorn)과 `nginx`를 명령 하나로 띄우게 정리했다.
- 정적 파일은 공유 볼륨으로 Nginx가 직접 전달한다.
- 수정이 남아 있어 EC2 최종 배포는 기능 확정 뒤 한 번 하기로 했다.

### ③ 평가

- 3차와 같은 30문항 · 같은 채점 스크립트로 4차 코드를 다시 평가했다 (공통 기준 57% → 63%, 최종 검증 53% → 93%, 자체 평가 B → A).
- RAGAS로 문서 질의응답 24문항을 처음 평가했고, search로 가야 할 질문이 general로 빠지는 문제를 찾아 분류기 개선안을 썼다.

### ④ 화면

- 3차 Streamlit 최종 화면과 하나씩 비교해 빠진 기능(첫 인사 · 진행 표시 · 처리 과정 · 결과 탭 7개 · 다시 시도 · 확인용 예제 30개 · 마크다운 표시)을 채웠다.
- 밝은 디자인 시안을 팀에 보여 준 뒤(14:53) 전체 화면에 적용했다.
- 팀원이 직접 눌러 볼 수 있게 로컬 서버를 임시 링크로 공유했다.

## 겪은 문제와 해결

| 문제 | 누가 | 해결 |
|---|---|---|
| 배포 스크립트(`docker run`)와 Compose 방식이 서로 다름 | ② | Compose(web + nginx)로 통일 |
| 서버에서 CSS가 404 | ④ · ① | `STATICFILES_DIRS` 추가 |
