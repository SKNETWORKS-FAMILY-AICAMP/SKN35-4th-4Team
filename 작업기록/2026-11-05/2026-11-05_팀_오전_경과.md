## 팀이 한 작업

### ② 분류기 보완

| 바꾼 것 | 내용 |
|---|---|
| 코드 규칙 먼저 | 코드가 없는데 옛 API 이름이 있으면 search, 코드가 없으면 migration 금지 (규칙 R1 · R2) |
| `no_code` 경로 | 코드 없이 변환을 요청하면 변환하지 않고 코드를 붙여 달라고 안내 |
| `route_error` | 분류 실패를 따로 기록해 평가에서도 실패로 셈 |
| 일반 답변 | temperature 0.7 → 0.3 |
| 평가 | 분류 오류를 평가 점수에 반영, A3(같은 질문 3번 분류) 확인 수정 |

### ③ 평가와 QA

- RAGAS 30문항을 실제 화면처럼 분류부터 거친 최종 답(e2e)으로 다시 평가했다: 근거 충실도 0.89, 사실 일치 0.48 (일반 LLM 0.32).
- 코드 QA (PR #11): 배포 이미지에서 DEBUG 끄기, 공개 SECRET_KEY 경고, 요청 본문 검증, 질문 길이 20,000자 제한, 검증 노드 결과 확인.

- 대화 삭제 API(`DELETE /api/langration/sessions/<id>/`)와 로그인 응답 시간 맞춤을 반영했다 (④가 화면을 고치며 시험 삼아 1차로 연결 → ①이 검토).
- ②의 분류기 변경이 `client.ask()` 호출 방식과 결과 모양을 바꾸지 않아 채팅 API는 수정 없이 동작했다.

## 겪은 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 배포 화면에 오전 수정이 안 보임 | EC2가 PR #8 이전 `dev`로 배포돼 있었음 | ②가 최신 `dev`로 재배포 |
| 재배포 후에도 예전 화면 | 브라우저가 예전 CSS · JS를 씀 | Ctrl+F5 안내 (버전 쿼리는 넣지 않기로) |
| 지운 대화가 목록에 다시 나타남 | 삭제 직전 목록 요청이 늦게 도착해 덮어씀 | 목록 요청 순서 검사, 삭제한 줄은 바로 지움 |
| 없는 아이디는 빨리, 틀린 비밀번호는 늦게 응답 | 있는 아이디일 때만 해시 계산 | 없는 아이디도 같은 계산을 하게 맞춤 |
| 배포 이미지에 DEBUG가 켜질 수 있음 | Dockerfile 기본값 없음 | `DJANGO_DEBUG=False`를 기본값으로 (③ QA) |
