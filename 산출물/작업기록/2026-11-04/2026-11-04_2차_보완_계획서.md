## 3. API 계약 초안 (4번 제안 → 1번 확정)

> 4번이 경로를 제안하고 1번이 그 경로로 받는 방식 (팀 합의). 로그인은 **비밀번호 없이 고유 아이디만** (3차와 같음).
> 응답은 모두 JSON, 실패는 `{"ok": false, "error": "이유"}`.

| 화면 동작 | 요청 | 보낼 값 | 받을 값 |
|---|---|---|---|
| 회원가입 (로그인 아래 작은 링크) | `POST /api/users/signup/` | `user_id` | `ok`, `user_id` · 중복이면 `error` |
| 로그인 | `POST /api/users/login/` | `user_id` | `ok`, `user_id` (Django 세션에 로그인 상태 저장) |
| 로그아웃 | `POST /api/users/logout/` | 없음 | `ok` |
| 새 대화 | `POST /api/langration/sessions/` | 없음 | `session_id` |
| 질문 · 예제 전송 | `POST /api/langration/chat/` | `session_id`, `message` | 아래 예시 (질문 · 답변은 백엔드가 자동 저장) |
| 이전 대화 목록 | `GET /api/langration/sessions/` | 없음 | `[{session_id, title, last_at}]` |
| 이전 대화 열기 | `GET /api/langration/sessions/<session_id>/` | 없음 | `[{question, answer, created_at}]` |

- 새 대화: ID는 버튼을 누를 때 받고, **목록에는 첫 질문을 보낸 뒤부터** 보임 (빈 대화가 쌓이지 않게)
- 이전 대화를 다시 열면 질문 · 답변만 복원 (결과 패널 복원은 🔜, 3차와 같음)
- 화면 주소: `/` → 로그인 안 했으면 `/login/`, 했으면 채팅 화면

채팅 응답 예시 (3차 `산출물/화면_결과_모양.md` 기준):

```json
{
  "ok": true,
  "route": "migration",
  "answer": "1.x 기준으로 바꿨습니다 ...",
  "result": {
    "target_version": "1.x",
    "original_code": "...",
    "migrated_code": "...",
    "changes": [{"old": "...", "new": "...", "kind": "native", "evidence_id": "imap-...", "source": "import_map"}],
    "verification": {"success": true, "attempts": 2, "message": "2회 만에 통과"}
  }
}
```

`route`가 `search` · `general`이면 `result`는 `null`이고 `answer`만 보여 줍니다.
