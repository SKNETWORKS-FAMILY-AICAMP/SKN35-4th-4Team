2. 평가 방법

2-1. 코드 변환 평가 (3rd 방식 그대로)

옛 LangChain 코드를 주고 1.x 로 바꾸게 한 뒤, 결과 코드를 LLM 이 아니라 코드로 채점합니다 (문법, 옛 import 없음, import 가 실제로 존재, 결과값 보존, 정답 import 포함 등 8개). 분류기가 질문을 맞는 경로로 보내는지(A1~A3)도 같이 봅니다.

2-2. RAGAS 문서 질의응답 평가 (새로 추가)

질문 24개: 마이그레이션 가이드 8 · 최신 문서 6 · import 위치 4 · 에러 메시지 3 · 문서에 없는 질문 3(모른다고 답하는지 확인). 각 질문에 정답 답변과 정답 문서 조각 ID 를 붙였습니다. 채점관은 gpt-4o, 챗봇과 일반 LLM 은 같은 gpt-4o-mini.

2-3. 두 가지 모드로 쟀습니다

search 모드 (부품 평가)모든 질문을 search 경로로 보내 검색 + 근거 답변 품질만 봄.
"RAG 부품이 얼마나 좋은가"
e2e 모드 (실제 화면 기준)그래프 전체를 돌려 분류기가 고른 경로의 답을 봄.
"사용자가 실제로 받는 답이 얼마나 좋은가"

두 모드의 차이 = 분류기가 질문을 잘못 보내서 생기는 손해. 그래서 검색 문제는 search 모드로, 분류 문제는 e2e 모드로 찾았습니다.

RAGAS 는 팀 uv.lock 과 패키지 버전이 충돌해서, 채점 스크립트만 따로 격리된 환경(uv run --script)에서 돌립니다. 팀 환경은 건드리지 않았습니다.

  • "코드가 있어야 migration", "코드 + 에러 → migration" 같은 코드로 확인할 수 있는 조건을 LLM 에만 맡김.

6-1. 알게 된 것

  • 챗봇 > 일반 LLM 은 세 세트 모두 같습니다. 다만 차이는 출제자가 시스템에서 멀어질수록 줄어듭니다 (+0.49 → +0.31 → +0.19). 제 질문 점수는 부풀려진 것이 맞고, 실제 성능은 GPT2 쪽 숫자에 가깝다고 보는 것이 안전합니다.
  • 분류 오류는 질문 말투에 달려 있습니다. GPT2 질문은 거의 모두 "1.x로 올리니까", "업그레이드하고" 처럼 버전 단어가 있어 분류기가 잘 맞혔고(오분류 1개), 제 질문 · GPT 질문은 "LLMChain 대신 어떻게?" 처럼 버전 단어 없이 물어 8~9개가 general 로 빠졌습니다. 5장 개선안(옛 API 이름 → general 금지, "대신 · 옮기면" 예외)이 노리는 것이 바로 이 말투라, 개선안은 여전히 필요합니다.
  • 데이터에 없는 마이그레이션 문서가 있습니다. chunks.jsonl 을 직접 찾아보니 LangGraph v1 마이그레이션 가이드 (ValidationNode, AgentStatePydantic 등)가 0개입니다 (GPT2 h06~h09). LangGraph 메모리 문서(h27~h30)도 없지만 이건 범위 밖이라 괜찮습니다.
  • 데이터에 내용이 있는데 검색이 놓친 질문도 있습니다 (GPT2 h03 TypedDict, h12 content_blocks, GPT g03 · g04). 문항 몇 개에 맞춰 고치면 다시 '본 문제'가 되므로 보류합니다.
  • '모른다' 판정: GPT 세트 g28 은 답이 "없습니다"로 시작했는데 판정 정규식이 놓쳤습니다 (채점 도구 문제).

모든 모델이 OpenAI 계열입니다 (챗봇 · 일반 LLM gpt-4o-mini, 채점 gpt-4o). 같은 계열 채점관 편향은 챗봇과 일반 LLM 둘 다에 걸리므로 '차이'는 비교적 안전하지만, 다른 회사 모델(예: Claude)로 한 번 더 채점하면 더 확실해집니다. GPT 가 쓴 정답(reference)은 아직 사람이 공식 문서와 대조하지 않았습니다.
